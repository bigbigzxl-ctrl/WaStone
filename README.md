### AMD(Xilinx)Artix XC7A35T / GoWin(GN1NZ)  — Closed-Loop FPGA Verification via WaStone
第一个FPGA里程碑已完成：娲石现在可以接管、修改、构建、编程、检测和验证真实硬件上的Xilinx/GoWin FPGA 项目！

娲石使用FPGA开发板，在 Xilinx Artix-7FPGA 项目上完成了完整的闭环验证工作流程。
这拓展了娲石的业务范围，使其不再局限于MCU固件，而是能够对真实硬件进行可重复、有测量支持的FPGA验证。

**做了啥:**

- 将一个基于Vivado的FPGA旧项目移植到WaStone命令行构建和程序控制之下（`build.tcl` / `program.tcl`）
- 将设计集成到 WaStone DUT 资产中(`assets_golden/duts/pa35t_starlite_led/`)
- 扩展RTL，将内部计数器位作为JM1连接器上的LA探针输出（4 × LVCMOS33 输出引脚）暴露出来。
- 使用 **WaStone** 逻辑分析仪以264MHz采样率同时采集了所有4个通道的数据。
- 编写了一个新的WaStone适配器脚本（`observe_fpga_counter_freq.py`），用于多通道频率、占空比和分频比验证。
- 运行端到端自动化验证——所有三个阶段均通过

**验证结果 (`counter_freq_verify.py`):**

| Stage | Check | Result |
|-------|-------|--------|
| Stage 1 | Frequency accuracy (4 channels) | **PASS** ±1% (observed ~0.56% offset) |
| Stage 2 | Duty cycle (50% target) | **PASS** ±6% (50 MHz is quantization-limited at 264 MHz LA) |
| Stage 3 | Adjacent-channel divide ratio (2:1) | **PASS** ±0.1% (max error 0.016%) |

**额外发现 — 时钟偏移测试:**
所有通道均显示出一致的约0.56%的频率偏移（约 5600 ppm），证实了FPGA时钟与WaStone测量参考时钟之间存在系统性的时钟差异。WaStone自动检测并分析了这一真实的硬件特性。

**为什么这个很重要:**

这一里程碑展示了WaStone下FPGA的实用工作流程：

修改RTL → 构建 → 编程 → 捕获信号 → 定量验证行为。

用于验证MCU固件的同一仪器基础设施（WaStone作为联网逻辑分析仪）同样适用于FPGA设计的测量后端——这表明WaStone的方法可以扩展到不同的器件系列。

## WaStone能做什么

WaStone 可以自动执行以下操作：

✔️ 生成固件

✔️ 安装工具链（如果缺失）

✔️ 构建项目

✔️ 烧录目标MCU/FPGA

✔️ 监控UART日志

✔️ 检测崩溃（内核崩溃/看门狗/重启循环）

✔️ 捕获并验证 GPIO 信号

所有这些都集成在一个自动化流程中。

---

## 为什么选择WaStone？

嵌入式开发仍然严重依赖手动迭代：

构建 → 烧录 → 观察 → 调试 → 重复

WaStone 通过以下方式打破了这一循环：

- AI 辅助项目生成
- 自动化构建和烧录
- 运行时监控
- 硬件信号验证

而且它适用于**真实硬件**，而非仿真环境。

---

## 工作原理（简化版）

```
Human → AI agent → Instrument → DUT (Target MCU)
```

其中：

- **AI agent** 负责协调工作流程并做出决策
- **Instrument** 提供调试访问权限和信号捕获功能
- **DUT** 运行真实固件并产生可观察的行为

---

> 构建、烧录、运行固件；

WaStone 将执行以下操作：

1. 生成固件
2. 编译固件
3. 刷写固件到目标设备
4. 运行固件
5. 捕获信号行为
6. 验证结果
7. 报告通过/失败

无需人工干预。

## 试试用两块开发板搭配WaStone（无需专用硬件）

您不需要 [WaStoneBody](https://github.com/bigbigzxl-ctrl/WaStoneBody) 来体验WaStone。

最简配置包括：
- 一块 ESP32-S3 开发板（测试板）
- 一块 RP2040 或 STM32 或 ESP32 开发板（被测设备）

第一块电路板是一个基于WiFi的信号检测仪，用于采集被测设备(DUT) 信号或生成激励信号，并通过WiFi与AI agent通信。

这使得WaStone无需专用硬件即可构建固件、烧录目标设备、运行代码并验证信号行为。

### 第一步连线

杜邦线分别连接:

- ESP32 GPIO A → RP2040 IN0
- ESP32 GPIO B → RP2040 IN1
- ESP32 GPIO C → RP2040 IN2
- ESP32 GPIO D → RP2040 IN3
- GND → GND

然后用中文跟WaStone说:


> 生成具有四种不同输出频率的固件，
> 构建、烧录、运行并验证信号。

WaStone 将自动进行编译、烧录、运行、测量和验证。

## 术语解释
WaStone 实验室由四个核心角色组成：组织者(Orchestrator)、被测设备(DUT)、仪器设备(Instrument)、连接(Connections)。


### 组织者(Orchestrator)
运行 WaStone 软件的系统。通常是 PC 或服务器。

职责包括：
- 流程编排和决策
- 构建和烧录控制
- 验证逻辑

### 被测设备(DUT: Device Under Test)
正在开发或验证的目标系统。

示例：
- STM32 开发板
- RP2040 Pico
- ESP32-S3 目标
- GW1NZ-lv1

运行固件并产生相应的行为。

### 仪器设备（Instrument）
与被测设备 (DUT) 交互的设备。

仪器提供以下功能：
- 调试访问（SWD / JTAG）
- 信号捕获和生成
- UART 监控
- 测量

### 连接（Connections）

定义被测设备 (DUT) 与仪器的连接方式。

示例：
- SWD → 仪器端口 P3
- DUT GPIO P4 → 采集卡 IN0

连接方式确保自动化测试结果可复现。

### 合起来就是:

```
Orchestrator → Instruments → Connections → DUTs
```
